╔══════════════════════════════════════════════════════════════════════════════╗
║  PART 1: HOW IT WORKS (The Architecture)                                    ║
╚══════════════════════════════════════════════════════════════════════════════╝

┌─ STEP 1: You Send a Message ───────────────────────────────────────────────┐
│                                                                              │
│  From your phone, laptop, or even a cron job:                               │
│                                                                              │
│    curl -X POST http://pinky.local:3100/send \                              │
│      -d '{"to":"pinky-claude", "body":"Create hello-world.sh"}'             │
│                                                                              │
│  The message goes into an inbox. That's it. You're done.                    │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘

┌─ STEP 2: The Poller Wakes Up ──────────────────────────────────────────────┐
│                                                                              │
│  On machine "pinky", a background daemon checks every 10 seconds:           │
│                                                                              │
│    [Poller] Checking inbox... 1 unread message!                             │
│    [Poller] From: maxyolo                                                   │
│    [Poller] Task: Create hello-world.sh                                     │
│    [Poller] → Launching screen session...                                   │
│                                                                              │
│  This happens automatically. No human intervention.                          │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘

┌─ STEP 3: Screen Session Spawns ────────────────────────────────────────────┐
│                                                                              │
│  "screen" is a terminal multiplexer (like tmux). It creates a detached      │
│  terminal that runs in the background.                                      │
│                                                                              │
│    screen -dmS "claude-work-12345" bash /tmp/wrapper-12345.sh               │
│                                                                              │
│  Translation: "Create a hidden terminal, run this script, don't wait."      │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘

┌─ STEP 4: Wrapper Executes Task ────────────────────────────────────────────┐
│                                                                              │
│  The wrapper script reads the context file:                                 │
│                                                                              │
│    cat /tmp/claude-context-12345.md                                         │
│    # Message: Create hello-world.sh                                         │
│                                                                              │
│  Then executes the task:                                                    │
│                                                                              │
│    echo '#!/bin/bash' > hello-world.sh                                      │
│    echo 'echo "Hello World!"' >> hello-world.sh                             │
│    chmod +x hello-world.sh                                                  │
│    ./hello-world.sh  # Test it                                              │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘

┌─ STEP 5: Cleanup & Exit ───────────────────────────────────────────────────┐
│                                                                              │
│  The wrapper logs completion and exits:                                     │
│                                                                              │
│    echo "✓ Task complete" >> ~/pinkyandbrain/claude-sessions.log            │
│    exit                                                                      │
│                                                                              │
│  Screen session terminates. No processes left behind.                       │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘

║  PART 6: COMMON QUESTIONS (FAQ)                                             ║
╚══════════════════════════════════════════════════════════════════════════════╝

Q: What happens if a task fails?
A: The wrapper logs the error to claude-sessions.log and the screen session
   stays open so you can attach and debug. Future: send alert message.

Q: Can I send multiple tasks to the same machine?
A: Yes! Each gets its own screen session. They run in parallel (limited by
   machine resources).

Q: How do I know when a task is complete?
A: Check the logs, or configure the wrapper to send a completion message back
   to your inbox. Future: webhook notifications.

Q: What if I want to stop a task mid-execution?
A: Find the screen session (screen -ls) and kill it (screen -X -S name quit).

Q: Does this work over the internet (not just local network)?
A: The cloud bus (Cloudflare Workers) enables internet-based messaging.
   Local bus is LAN-only. Both are supported by the poller.

Q: What's the difference between local bus and cloud bus?
A: Local bus: Fast, LAN-only, no auth needed, perfect for home network
   Cloud bus: Internet-accessible, API key protected, for remote work

Q: Can I schedule tasks (like cron)?
A: Yes! Either use cron to send messages, or use the cloud bus workflow
   scheduler. Example:

     0 2 * * * curl -X POST http://pinky.local:3100/send -d '...'

   This sends a task every night at 2am.

Q: What about privacy/security?
A: Tasks run on YOUR machines with YOUR code. Messages are API key protected
   on cloud bus. Nothing leaves your infrastructure except metadata.
